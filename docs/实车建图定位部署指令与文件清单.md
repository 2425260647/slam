# Scout 实车在线建图定位部署指令与文件清单

本文只处理 Cartographer 在线 2D 建图定位，不启动或修改外部 A*、TEB
规划器。目标机为 Ubuntu 18.04 + ROS Melodic，Catkin 工作区为：

```text
/home/xcy/scout_0_ws
```

## 一、需要复制的源码

从开发机复制以下目录到小车工作区的 `src/` 下：

```text
src/cartographer/
src/cartographer_ros/
src/my_navigation/
```

`cartographer` 和 `cartographer_ros` 必须整体同步，不能只复制某一个 `.cc`
文件，因为创新点一和创新点二同时涉及头文件、Proto、Lua 解析和 ROS 发布。

需要确认或同步的静态外参文件：

```text
src/function_module/launch/common/static_tf.launch
```

本项目实车雷达外参为：

```text
base_link -> laser_link
x=0, y=0, z=0.33521 m, yaw=-1.5708 rad
```

不要复制以下开发机产物：

```text
bags/
build*/
devel*/
install*/
paper_exp/运行目录/
*.pbstream
*.log
```

`function_module` 暂时保留，因为外部规划系统可能引用其中的 footprint、TF
或 costmap 参数；但在线 SLAM 时不要启动其中会拉起 `map_server` 或 AMCL 的
旧导航入口。

## 二、Melodic 端编译

```bash
source /opt/ros/melodic/setup.bash
cd /home/xcy/scout_0_ws

rosdep install --from-paths src --ignore-src -r -y

catkin_make_isolated \
  --install \
  --use-ninja \
  --force-cmake \
  --only-pkg-with-deps cartographer_ros my_navigation \
  --make-args -j6

source /home/xcy/scout_0_ws/install_isolated/setup.bash
```

Noetic 下的 `build_isolated/devel_isolated/install_isolated` 不能直接复制到
Melodic 使用，必须在小车端重新编译。

## 三、启动顺序

### 1. 启动底盘与雷达

使用小车现有驱动启动文件，确认以下输入存在：

```bash
rostopic hz /velodyne_points
rostopic hz /odom
```

### 2. 启动静态外参

如果底盘启动文件没有提供该 TF，只启动一次：

```bash
source /opt/ros/melodic/setup.bash
rosrun tf2_ros static_transform_publisher \
  0 0 0.33521 -1.5708 0 0 base_link laser_link
```

不能同时运行旧的 `0.17 m` 高度外参发布者。

### 3. 启动在线 Cartographer

```bash
source /opt/ros/melodic/setup.bash
source /home/xcy/scout_0_ws/install_isolated/setup.bash

roslaunch my_navigation real_scout_online_slam.launch \
  cloud_topic:=/velodyne_points \
  odom_topic:=/odom \
  rviz:=false
```

该入口只启动点云投影、扫描质量门控、Cartographer、`/map` 发布和健康
监控；不会启动底盘、雷达、A*、TEB、AMCL 或 `map_server`。

### 4. 验收 SLAM 输出

```bash
rostopic hz /scan
rostopic hz /map
rostopic echo -n 1 /map/header
rosrun tf tf_echo map odom
rosrun tf tf_echo map base_footprint
rosrun tf view_frames
```

必须满足：

```text
/scan 持续约 10 Hz
/map 持续更新
map -> odom 由 Cartographer 提供
odom -> base_link 由底盘唯一提供
base_link -> base_footprint 和 base_link -> laser_link 唯一且稳定
```

### 5. 启动外部 A* + TEB

最后启动小车已有的规划模块。不要启动会同时拉起 `map_server`、AMCL 或
第二个 Cartographer 的旧导航入口。规划模块应读取：

```text
/map
/scan
/odom
map -> odom -> base_footprint
```

## 四、TF 所有权

生产模式采用下面的唯一发布关系：

```text
Cartographer: map -> odom
Scout 底盘:   odom -> base_link
机器人模型:   base_link -> base_footprint
静态外参:     base_link -> laser_link
```

生产 Lua 是 `cartographer_scout_online_navigation.lua`，其中：

```lua
published_frame = "odom"
provide_odom_frame = false
use_odometry = true
```

如果发现两个节点同时发布 `odom -> base_link`，必须先停掉重复发布者；否则
TEB 和 costmap 会出现位姿跳变。

## 五、话题交接表

| 输出 | 类型/TF | 规划用途 |
|---|---|---|
| `/map` | `nav_msgs/OccupancyGrid` | global costmap、A* |
| `/scan` | `sensor_msgs/LaserScan` | local costmap 障碍物 |
| `/odom` | `nav_msgs/Odometry` | TEB 速度和短期运动 |
| `map -> odom` | TF | Cartographer 全局校正 |
| `odom -> base_link` | TF | 底盘连续运动 |
| `base_link -> base_footprint` | TF | costmap 机器人基座 |
| `base_link -> laser_link` | TF | 雷达数据变换 |

`/local_occupancy_grid` 是本项目的显示和诊断输出，不是标准 TEB 必需输入；
标准 local costmap 直接订阅 `/scan`。

## 六、当前不使用 PBStream 的原因

本部署模式是首次进入环境时在线建图，Cartographer 从空轨迹开始不断扩展
`/map`，所以启动时不加载 PBStream。PBStream 只用于之后已有地图上的纯定位
启动流程，本次不需要。

## 七、必须注意的地图安全问题

此前三条长走廊 bag 都观察到回程自由空间射线可能清除早期墙体。正式部署前
必须完成 `repeat_03` 的 hit/miss 参数调优，再用 `repeat_01` 和 `repeat_02`
独立验证。完全关闭 `insert_free_space` 只用于根因对照，不作为正式配置。
