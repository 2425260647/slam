## 2. 原问题

二维点云协方差是在当前重力对齐 tracking 平面中计算的，最大特征值对应方向记为
`v_long_tracking`。Ceres 优化变量中的平移误差却是 local-SLAM 坐标系中的
`e_local = p_local - p0_local`。

旧代码直接使用 tracking 方向构造矩阵，再将矩阵乘 local-SLAM 误差。小车航向变化时，
矩阵纵向可能不再对应物理走廊纵向；而且方向平滑也在随车体旋转的坐标系中进行，掉头和
转弯附近容易发生方向混合。

## 3. 修正方法

源码位置：

- `src/cartographer/cartographer/mapping/internal/2d/scan_matching/ceres_scan_matcher_2d.cc:251`
- `src/cartographer/cartographer/mapping/internal/2d/scan_matching/ceres_scan_matcher_2d.cc:311`
- `src/cartographer/cartographer/mapping/internal/2d/scan_matching/ceres_scan_matcher_2d.cc:461`

在构造各向异性矩阵前，使用 Ceres 初始位姿中的二维旋转完成：

```text
v_long_local = R(initial_pose_estimate.yaw) * v_long_tracking
v_lat_local  = R(initial_pose_estimate.yaw) * v_lat_tracking
S_local      = R_local * diag(w_long, w_lat) * R_local^T
r             = S_local * (p_local - p0_local)
```

符号对齐、时间平滑和信息矩阵构造现在全部在稳定的 local-SLAM 坐标系中进行。没有改变
Sigmoid、平滑系数、Lua 参数、Ceres CostFunction 结构或创新点二。

ROS 发布层位于：

- `src/cartographer_ros/cartographer_ros/cartographer_ros/node.cc:345`

核心方向保持为 local-SLAM 语义；发布 `/degeneracy_direction` 前再乘当前
`local_to_map.rotation()`，使该话题统一表达 map 坐标方向。由于消息类型仍按原需求保留
为 `geometry_msgs/Vector3`，其自身没有 `frame_id`，项目文档已明确约定其语义为
`map_frame`。离线分析不能再乘一次机器人 yaw。

## 6. 方向结果

以同一次在线轨迹的 PCA 主轴作为走廊方向代理，筛选 `D_conf >= 0.8`：

| 指标 | 旧版 repeat_03 | 修正后 repeat_03 |
|---|---:|---:|
| 高置信方向误差中位数 | 19.99 deg | 2.64 deg |
| 高置信方向误差 P90 | 65.52 deg | 5.89 deg |
| 修正后最大误差 | - | 13.76 deg |
| 修正后有效高置信样本 | - | 11241 |

中位误差相对下降约 `86.8%`，P90 相对下降约 `91.0%`。这说明坐标转换和在
local-SLAM 中进行方向平滑确实解决了原有的主要方向错置问题。

证据边界：轨迹 PCA 是代理参考，不是用全站仪实测的物理走廊轴，因此可以写成“方向
一致性显著提高”，暂时不能写成“绝对方向误差达到 2.64 deg”。
